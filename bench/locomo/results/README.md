# LoCoMo — committed evidence

These are the **unmodified reports** the harness emitted for the runs quoted in the
repository README, except for one disclosed redaction (see bottom). They are checked in
so any published number can be traced to a command, a git SHA and a dataset hash.

**The harness never writes here.** Your own runs land in `out/` (gitignored).

Everything below was produced at memory-core `5ea3852`, on LoCoMo
`sha256:79fa87e90f040813…`, corpus `sha256:26ec6082f1589897…`, against
**mem0 OSS 2.0.14** run by us through the same harness.

## Files

| file | what it is |
|---|---|
| `mode_a.json` | retrieval metrics for all 10 system rows, n = 1,531 answerable questions |
| `mode_a.txt` | the same, as printed tables |
| `mode_b.json` | QA accuracy per (system, k), full-set denominators |
| `mode_b.txt` | the same, as printed tables, plus token/cost accounting |
| `oracle_matched.txt` | QA accuracy restricted to the oracle's question set (n = 233) |
| `audit.txt` | leakage audit — all checks PASS |
| `mem0_attribution.txt` | how mem0's consolidated memories were mapped back to gold turns |
| `reasoning_sensitivity.txt` | does disabling the model's reasoning mode change what mem0 stores |

`out/mode_b.jsonl` (12 MB of per-question reader/judge transcripts) is **not** committed.
It is the input to `score_mode_b.py` and `oracle_matched.py`, and is regenerated by a
Mode B run.

## Which artifact backs which published table

### README table: "3. LoCoMo — … head-to-head with mem0" (rank metrics)

**`mode_a.json`** → `.systems[] | {system, overall}`, n = 1,531.

| README row | artifact `system` | R@1 / R@5 / R@10 / R@30 / MRR / nDCG@10 |
|---|---|---|---|
| mem0 | `mem0` | .345 / .635 / .694 / .783 / .534 / .548 |
| memory-core hybrid (`rrfK=5`) | `memory-core-hybrid-rrf5` | .344 / .620 / .709 / .817 / .524 / .544 |
| memory-core BM25-only | `memory-core:in-memory` | .332 / .555 / .626 / .726 / .482 / .494 |
| bm25 baseline | `bm25` | .303 / .507 / .578 / .673 / .437 / .450 |
| random control | `random` | .002 / .012 / .020 / .057 / .012 / .010 |

Command: `./mode_a.sh --with-hybrid` (plus `--with-mem0` for the mem0 rows).

Three system rows exist in the artifact that the README does not quote, and they matter:

- **`memory-core-hybrid-rrf60`** (R@10 .666) — the provider's *default* RRF constant, and
  it is **worse** than `rrfK=5` on this dataset. The README quotes only the `rrfK=5` row.
- **`mem0-metadata`** and **`mem0-textmatch`** — deliberate lower and upper bounds on
  mem0's attribution. mem0 rewrites and consolidates, so a retrieved memory is not a
  corpus turn; three attribution channels bracket the answer instead of asserting one.
  The quoted `mem0` row is the **middle**, exact event-log channel. The upper bound
  (`mem0-textmatch`, R@10 .703) is still below memory-core hybrid's .709, so the README's
  R@10 claim survives the most mem0-favourable attribution.
- **`memory-core:dual-layer`** and **`memory-core:enhanced`** — the deprecated providers,
  at R@10 .295 and .099.

### README table: "Ingest cost for the same 5,882 conversation turns"

`mode_a.json` → `.systems[].ingest` (`seconds`, `llm_calls`, `prompt_tokens`, `usd_cost`)
and `.systems[].mean_latency_ms`. mem0's $3.45 / 5,882 LLM calls / 51.6 M prompt tokens

prompt tokens, $3.70 — that is the cost of *scoring*, paid identically for every system,
and is not part of the ingest-cost table.

## Reading the audit

`audit.txt` is the leakage audit, and it is the reason to believe the rest. It verifies,
against the raw upstream file, on every run:

1. Every indexed document decomposes into **verbatim dialogue turn text**. The
   `observation`, `session_summary` and `event_summary` annotation fields — which are
   written by summarising the dialogue and would leak answers — are never ingested.
   5,882 turns verified.
2. The query sent to each system is **byte-identical** to the dataset question, with no
   gold answer appended. 1,986 questions verified.
3. No answer/gold field is referenced anywhere in the ranking code paths.
4. `src/` contains no LoCoMo-specific literals.
5. The random control sits at analytic chance (empirical R@10 .0198 vs analytic .0170).
   A leaking harness lifts the random control too, so this is the sharpest single test.
6. Every turn-id system stayed inside its own conversation's corpus (all 0 foreign refs).

Two findings are reported as INFO rather than hidden:

- 3 of 1,986 questions contain their own gold answer, because LoCoMo phrases them as
  "would X prefer A or B?". That is a dataset property applied identically to every
  system, not a harness leak.
- `memory-core:dual-layer` returned 20,207 synthesized (non-turn) records out of ~45,930
  retrieval slots. It is a consolidating provider, so its score is a **lower bound**
  unless attributed the way mem0 was.

## Reading the reasoning-sensitivity check

`reasoning_sensitivity.txt` quantifies the one configuration choice that could have moved
mem0's ceiling. `deepseek-v4-flash` is a reasoning model; left at its default it spends
the whole token budget on the reasoning trace and returns `content=null`, which mem0
cannot parse — silently dropping ~2% of memories. The harness disables reasoning for the
answerer, the judge and mem0's write path alike, so one model behaviour is used
everywhere. The artifact shows the effect of that choice measured on matched
conversations and a matched turn prefix, rather than assumed to be zero.

## Redaction

`mode_a.json` carries a top-level `_redaction` field recording that infrastructure
identifiers — absolute filesystem paths on the box the run executed on — were rewritten
to placeholders when these files were imported into the public repository. Git SHAs,
dataset and corpus hashes, model ids, every metric and every denominator are exactly as
the harness emitted them.
